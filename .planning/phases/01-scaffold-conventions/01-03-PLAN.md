## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| parent repository (`../ipv-demo`) → this repository | An inherited design layer crosses here once and must not drift afterwards |
| design register → build gate | A below-floor contrast value can only enter the build through the exemption register |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-07 | Information disclosure / usability denial | rendered text inks | mitigate | Every override in `tokens.capture.css` carries its measured ratio as a comment; `docs/design/decorative-exemptions.json` has exactly four entries and `check-tokens.mjs` asserts that shape, so plan 01-06's contrast check cannot be widened by an unmeasured exception. |
| T-1-11 | Tampering | `app/styles/tokens.inherited.css` | mitigate | SHA-256 and byte-length asserted against the pinned parent digest on every build (D-12); the parent is not present on Vercel, so the hash is the only available proof. |
| T-1-12 | Tampering | `tokens.capture.css` shadowing inherited names | mitigate | `check-tokens.mjs` fails on any Capture declaration that also exists in the inherited layer other than `--viewer-ink-dim`, so an inherited token cannot be silently redefined (D-12, D-13). |
| T-1-04 | Tampering | the design floor | accept | The 13px floor, the single-weight-per-family rule and the ink-permission list are conventions enforced by review and by plan 01-06's contrast and axe checks, not by a dedicated linter; the residual risk is a new component using a forbidden ink, which the contrast pairs manifest catches only for pairs it lists. |
