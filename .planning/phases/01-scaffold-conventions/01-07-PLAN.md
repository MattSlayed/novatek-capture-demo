scripts/verify.mjs
- `export const STEPS: Array<{ id: string, command: string, args: string[], shell?: boolean, env?: object, capture?: string }>`
  — the ordered gate, exactly as D-20 states it.
- `export async function runSteps(steps, run): Promise<number>` — invokes each step in order via
  the injected `run` function, returns the first non-zero exit code and does not invoke any
  later step; returns 0 only if every step returned 0.
- Execution is guarded by `import.meta.main` so the test can import `STEPS` and `runSteps`
  without running the gate.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| developer workstation → git → GitHub Actions | The gate's authority depends on it running somewhere the developer cannot edit per-run |
| GitHub Actions check → Vercel production aliasing | A red job must hold promotion; this is the link that turns a failing check into a stopped deployment |
| Vercel build container → the same script | The build runs the same file with one environment-marked exclusion, not a different command |
