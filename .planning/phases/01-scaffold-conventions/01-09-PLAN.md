<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public internet → the production deployment | The boundary the whole phase exists to label; crossed by a stranger with a phone and no session |
| GitHub Actions check → Vercel production aliasing | The registration made here is what converts a failing check into a stopped deployment |
| developer → Vercel dashboard | Settings that no command can read or set; the only human-only dependency in this phase |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-20 | Information disclosure | Deployment Protection left on | mitigate | Confirmed off in Task 1 and re-asserted by `check-deployment.mjs`, which treats a `_vercel/sso` redirect as a named failure — so a logged-in developer's successful open cannot be mistaken for public reachability (D-24). |
| T-1-18 | Tampering / Elevation of privilege | the Deployment Check binding | mitigate | Registered against the exact job id `verify` and demonstrated in Task 2 by pushing a deliberate governed-literal duplicate and confirming the deployment is created but not aliased (D-22, REQ-SM-5). |
| T-1-02 | Repudiation | build identity in production | mitigate | System Environment Variables exposed in Task 1 so `VERCEL_GIT_COMMIT_SHA` resolves; the Preview build log is read to confirm `NEXT_PUBLIC_BUILD_ID` is a commit sha and not the development fallback (D-03, D-24). |
| T-1-14 | Denial of the disclosure | the ribbon on a real handset | mitigate | The phone check covers what no headless scan can: rendering order at the default and 200% text sizes, tappability, and the absence of any dismissal affordance, on both an iPhone and an Android handset (REQ-FR-48, roadmap success criterion 2). |
| T-1-19 | Denial of service | the browser install in Vercel's build | mitigate | Falsified directly in Task 2 by overriding the Install Command on a throwaway branch and reading the build log; the outcome is recorded and can only widen Vercel's build command (D-22, RESEARCH.md A1). |
| T-1-21 | Tampering | the throwaway demonstration branch | mitigate | The branch carrying the deliberate duplicate is deleted and never merged; `npm run verify` is re-run green on `dev` afterwards, so the demonstration leaves no residue. |
</threat_model>
