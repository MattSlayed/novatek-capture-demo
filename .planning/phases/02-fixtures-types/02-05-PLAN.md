<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| the authored plane → the record it cites | An authored observation is a sentence somebody wrote; the citation is the only thing tying it to a record, and the comment is the only human-readable half of that tie |
| the fixture file over time → the audit made against it once | The provenance check is performed once by a person; every later edit to `plant.ts` or `observations.ts` can silently falsify it |
| a citation's *form* → a citation's *truth* | A resolvable id and a matching quote are machine-checkable; whether the record supports or only situates the wording is not, and must not be presented as if it were |

Fixtures prove a one-word change and a missing unit each exit non-zero (D-10, D-11). |
| T-2-18 | Spoofing | a `drawn_from` that looks resolvable and names nothing citable | mitigate | Task 2 builds the id space as exactly the union of the copied `CitedFact` ids and the `Deviation` `id` keys, and ships fixtures citing a machinery id and the `NCR-2026-0118` `ncr_number` form, both of which must exit non-zero — the two forms most likely to be written by mistake (D-09). |
