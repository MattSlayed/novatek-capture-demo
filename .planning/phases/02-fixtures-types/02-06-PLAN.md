<objective>
Run the human provenance check (FR-21a): present the review sheet, take the reviewer's verdict on every
row, apply the verdicts, and write the signed `docs/analysis/provenance-check.md`.

Purpose: AD-15 names this the one gate in the whole build that no command can run. The automated half —
that every `drawn_from` resolves and every quoted comment still equals the record — is green before this
plan starts. What is left is the judgment a machine cannot make: whether a wording is an honest
inference the cited record supports, or a wording the record only situates. The phase does not close
without it, and no executor may close it alone.

Output: one signed dated artefact, plus whatever changes the reviewer's verdicts require in
`lib/data/observations.ts`.

**This plan is `autonomous: false` and Task 2 is a blocking human gate.** It is never auto-approved.
`workflow.auto_advance` does not apply to it, and an agent that has not received the reviewer's own
words in the session has not passed it. If the reviewer is unavailable, the plan stops and waits; it
does not proceed on an assumed verdict.
</objective>

  <action>
Perform no sign-off yourself. Present the review sheet, row by row, in the session, then stop and wait.

When the reviewer has answered every row, apply the verdicts and only the verdicts:

A row answered **confirmed** is recorded as `confirmed` and nothing in `observations.ts` changes.

A row answered **reword** takes the wording the reviewer supplies, verbatim. Never reword on your own
initiative and never improve a wording the reviewer supplied (D-04). Update `wording` in
`lib/data/observations.ts` and the sheet's wording column together.

A row answered **re-cite** takes the record the reviewer names. Update `drawn_from`, rewrite the `// cites`
comment from the newly cited record's live fields under the same fixed form the file already uses, and
update the sheet's cited-record and record-sentence columns.

A row answered **drop** is removed from `lib/data/observations.ts` entirely, its row is kept in the sheet
with the verdict `dropped` so a later reader sees it was considered, and the expected-count constant in
`scripts/check-observations.mjs` is decremented in the same commit. The set may shrink only this way.

After applying any reword, re-cite or drop, re-present every changed row to the reviewer with its record's
own sentence beside it and take a second answer on it, before anything is signed (D-04). Run
`node scripts/check-observations.mjs` and `npx tsc --noEmit` after the edits and before re-presenting, so
a changed row is presented against a green check rather than a hopeful one.

Then, and only then, write the signed file: fill the verdict column for every row, write the reviewer's
name in the reviewer column exactly as he gives it at the checkpoint, write the date, and close with the
`Recorded <date>.` line the other analysis artefacts use. One reviewer, no counter-signature line: the
SHEQ manager is not involved in this phase (D-01).

Finally, append one `test()` to `scripts/check-fixture-shape.test.mjs` that reads
`docs/analysis/provenance-check.md` and asserts its structure: the main table has one row per entry in
`OBSERVATIONS`, every row's observation id matches an id in `OBSERVATIONS` or carries the verdict
`dropped`, every verdict cell holds one of `confirmed`, `reworded`, `re-cited` or `dropped`, and the file
carries a non-empty reviewer name and a date. Give the test a comment saying plainly what it is and is
not: a structural completeness guard so a later edit cannot blank a verdict, never a substitute for the
judgment recorded in those cells (AD-15, FR-21a).
  </action>
