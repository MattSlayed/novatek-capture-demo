<objective>
Close the phase's machine-checkable half: export `FIXTURE_VERSION` from `lib/data/fixtures.ts` with the
content hash pinned beside it, and wire the recompute-and-compare check into `npm run verify`.

Purpose: AD-6 binds a decision to a snapshot. That is only true if the snapshot has a name and the name
cannot drift from the content it names. The pin is what makes a fixture edit a deliberate act — content
changes, hash changes, `verify` fails until the version is bumped and the pin re-cut in the same commit.

This runs last on purpose. The hash covers `observations.ts`, and the provenance checkpoint in plan
02-06 may reword, re-cite or drop a row; a pin cut before the sign-off would be a pin of a draft.

Output: one config module, one check with its failing fixture, one `verify` step, two `.gitattributes`
entries.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| the fixture snapshot → a decision bound to it | AD-6 binds a decision to a fixture version; if content can move under a fixed version, every decision recorded against it is unverifiable afterwards |
| this workstation → GitHub Actions and Vercel | The same commit checks out with different bytes on Windows and Linux; a hash that does not account for that proves nothing about the content |
| the pin → the checker | If the checker reads its expected value from anywhere other than the tree it is checking, its fixtures prove nothing |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2-27 | Tampering | fixture content changing without a re-pin or a version bump | mitigate | Task 2's check recomputes the SHA-256 over the four files on every `verify` run and fails naming both digests; its fixtures prove a one-character change in `observations.ts` and in `plant.ts` each exit non-zero (D-14). |
| T-2-28 | Repudiation | a pin that differs by platform and so proves nothing | mitigate | CRLF is normalised to LF before hashing, inside the script, where an editor's setting cannot reach it; the CRLF fixture test — all four files converted, pin untouched, check still exits 0 — is the direct proof, and `.gitattributes` `text eol=lf` is defence in depth beside it (RESEARCH Pitfall 2). |
| T-2-29 | Spoofing | the fixture version confused with the build id | mitigate | `FIXTURE_VERSION` takes the sibling's `SCENE_VERSION` shape, `capture-fixtures/YYYY.MM.N`, which no build id resembles; the check asserts the shape; and `fixtures.ts` is asserted to contain no reference to `BUILD_ID`, `rev-parse` or `process.env` (D-13, AD-6). |
| T-2-30 | Tampering | a check whose fixtures cannot fail | mitigate | The script imports the pin from the working directory's own `lib/data/fixtures.ts` rather than from a fixed path, so a fixture tree's mutated content is compared against that tree's own pin; without this the mutation tests would pass vacuously and the check would be theatre. |
| T-2-31 | Repudiation | a pin cut over a draft | mitigate | This plan depends on `02-06` and runs in the last wave, after the provenance checkpoint has applied every reword, re-cite and drop, so the pinned snapshot is the reviewed one rather than the drafted one (D-02, D-04, D-14). |
</threat_model>
