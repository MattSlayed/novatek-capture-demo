<objective>
Build the two modules every route in this phase goes through: the memory store that is the whole of the
record, and the responder that is the whole of the wire format.

Purpose: AD-10 makes the store per-instance and self-describing; AD-11 makes the responder the only
place a `Response` is constructed, which is what makes AD-4's byte-identical not-found true by
construction rather than by discipline. If a route can hand-write a 404, FR-6 is void before a single
test runs.

Output: one store with its unit test, one pure transport contract with its unit test, and one
constructor module proved over HTTP later by the route suite.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| one account's records → another account's records | A shared global cap with a naive eviction lets a flooding account delete a victim's records; the seed's "within the offending account first" rule is the boundary |
| a route handler → the wire | Any route able to construct its own `Response` can produce a 404 that differs from every other 404, which is the whole of FR-6 |
| the server's clock → the device's claim | `last_contact` must come from the server's own clock; a value taken from a body would let a device move its own clamp floor |
