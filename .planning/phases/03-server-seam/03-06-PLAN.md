<objective>
Turn the two halves of FR-17's no-model claim into build rules: the authored modules declare exactly
`(assetId, fixtureSet)` and can reach no capture payload, and the dependency manifest contains no
library that could run one.

Purpose: REQ-FR-17 is verified by analysis plus inspection, and this repository's standing convention
(Phase 1 D-20, D-23) is that an analysis claim which is not a check is a claim a future commit can
quietly break. Both rules are cheap, both are source-side, and both ship with a fixture proving they
fail.

Output: two check scripts, two fixture tests, two new gate steps, and a step count of twenty-one.
</objective>

**Assertion 1 — the declared inputs.** Read `lib/verify/authored.ts` and `lib/proposals/derive.ts` as
text. For each, require a declaration matching `export function authoredMatch(assetId: string,
fixtureSet: string)` and `export function authoredProposals(assetId: string, fixtureSet: string)`

**Assertion 2 — the import graph.** Reuse `check-register-isolation.mjs`'s helpers verbatim:

the rule's own prose cannot trip it — strip lines matching `^\s*(//|\*|/\*)` before counting, and say in
a comment that a naive substring count over a file that documents itself is self-invalidating, which is
why the filter is there.

Carry `check-register-isolation.mjs`'s honest-caveat comment into this script's header in your own
words: the specifier extraction is a regex, not a parser, so a dynamic `import()` built from a runtime
string and a re-exported binding under a different name are both outside what this can catch.
