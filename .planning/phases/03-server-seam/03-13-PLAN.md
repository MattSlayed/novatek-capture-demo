Export:

- `HEADER_EXCLUSIONS` — an array of `{ name, reason }`, lowercased names, exactly these entries with a
  one-line reason each, per D-11:
  `date` (a per-response timestamp), `connection` and `keep-alive` (hop-by-hop, set by the HTTP layer),
  `transfer-encoding` and `content-length` (body framing varies between a local `next start` and the
  platform), `vary` (framework-emitted router hint, constant per method but not ours — observed
  empirically on every Route Handler response), `server` (platform-added), `etag` (the platform may add
  one), and the `x-vercel-` prefix family (routing and cache identifiers the platform adds). Record the
  prefix entry as a prefix rather than a fixed name, and comment that the list is the local observation
  plus what CONTEXT.md's D-11 anticipates, and that the human-run curl suite against a real deployment
  is what confirms it.
- `assertUniversalHeaders(response, label)` — asserts `cache-control` is exactly `no-store`,
  `x-cap-store` is present and non-empty, and `x-cap-instance` is present and non-empty. Throws an
  `AssertionError` naming `label` and the missing header. Every request the suite makes passes its
  response through this, success and error alike (NFR-F1).
- `assertNoSuccessOnlyHeaders(response, label)` — asserts no header whose name matches an entry in
  `HEADER_TABLE` with `scope: "success-only"` is present. Used on every not-found and every error.
- `compareResponses(a, b, label)` — the D-11 comparator. Takes two `{ status, bodyText, headers }`
  records, asserts the statuses are equal, asserts the body bytes are equal (compare the raw text, not
  a parsed object — the requirement is byte-identity, and two different objects can serialise to the
  same JSON while two identical objects can serialise differently), then builds the header maps with
  every excluded name and every `x-vercel-` prefixed name removed and asserts the two maps deep-equal.
  On failure, report the first differing header by name and both values, because a bare "not equal" on
  a header map is unreadable at 3 a.m.
- `cookieJar()` — returns `{ fetch(url, init), cookies }`, capturing every `set-cookie` from a response
  into a name→value map and replaying it as a single `Cookie` header on the next request. Handle the
  `maxAge: 0` clear by deleting the name from the map. Comment that `node:test` plus `fetch` has no
  cookie jar, that there is no in-repo analog, and that this is the smallest thing that does the job.
- `snapshot(response)` — an async helper returning `{ status, bodyText, headers }` with `headers` as a
  plain lowercased object, so `compareResponses` never has to touch a live `Response`.

Create `scripts/server/route-assertions.test.mjs` — the D-23 fixture proof, and deliberately a
`.test.mjs` so the existing `fixture-suite` glob collects it. It needs no server: build synthetic
`{ status, bodyText, headers }` records by hand. Assert:
- `assertUniversalHeaders` passes for a record carrying all three and **throws** for a record missing
  `x-cap-instance`, for one missing `x-cap-store`, and for one whose `cache-control` is
  `private, no-cache` rather than `no-store`. This is the self-test the suite ships with: it proves the
  suite fails when a response lacks a universal header;
- `assertNoSuccessOnlyHeaders` throws for a record carrying `x-cap-order` and passes for one carrying

- `compareResponses` passes for two records differing only in `date`, `vary`, `x-vercel-id` and

  byte of `bodyText`;
- `compareResponses`'s failure message names the differing header;
- `HEADER_EXCLUSIONS` has a non-empty `reason` on every entry, and contains no `x-cap-` name — excluding
  one of our own headers would defeat the whole comparator;
- `cookieJar` captures a `set-cookie`, replays it as a `Cookie` header, and drops it after a clearing
  `set-cookie` — drive it with a stub fetch rather than a real one.
