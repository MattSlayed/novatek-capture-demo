<objective>
Build the time-on-order surface: the one screen whose entire purpose is the provenance of the
instants in an artisan's accrued record.

Purpose: FR-58 requires the artisan to read their own accrued record in full — every segment, its
source, any measured offset, nothing withheld — with the stated limitation that no route exists
to contest a segment. The surface renders exactly the fields `OrderClock` carries and no figure
the phone derived, so "nothing withheld" is provable rather than asserted.

Output: one surface and its CSS module. It is not reachable yet; plan 04-11's switcher renders it.
</objective>

TimeOnOrder: { account: Artisan; orderId: string;
               onRefused: (code: ConflictCode, sentence: string) => void }

From lib/client/clock.ts (plan 04-03), all unit-tested there:
  segmentRows(clock)   → per segment, the ordered term/value pairs with the presence rules
  formatInstant(iso)   → { the server's byte-exact ISO string, the YYYY-MM-DD HH:MM:SS reading }
  formatDuration(s)    → H:MM:SS

The five pairs and their presence rule (04-UI-SPEC Decision 2):
  SOURCE + mark + word        always
  STARTED + instant           always
  DEVICE CLAIMED + instant    only where segments[].device_claimed_opened_at is present
  MEASURED OFFSET + duration  only where segments[].device_offset_s is present
  ENDED + instant, or RUNNING always
</interfaces>
