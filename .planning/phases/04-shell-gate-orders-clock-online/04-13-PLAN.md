<objective>
Close the four claims this machine's harness cannot reach, on a real Android handset and a real
iOS handset against a deployment, and write the result down whether it passed or not.

Purpose: `navigator.vibrate` is reported present by this project's headless browser, so CI can
only prove the call site is feature-tested; hidden-tab timer throttling did not reproduce in
headless Chromium at all; a text-only 200 % scale cannot be emulated where the type roles are
declared in pixels; and no automated tool checks whether a screen reader actually announces a
heading that `document.activeElement` has become. Those are the four gaps the research logged,
and a device pass is the only thing that closes them. The practice is Phase 2's provenance check
and Phase 3's curl suite: the result is recorded with the build id, pass or fail.

Output: one analysis document, and the developer's own answer recorded verbatim in it.
</objective>
