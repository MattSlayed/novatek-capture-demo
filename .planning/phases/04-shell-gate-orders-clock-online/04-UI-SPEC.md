# Phase 4 — UI Design Contract

**Phase 4: Shell, gate, orders, clock (online)** — novatek-capture-demo (NOVATEK Capture, designed preview)

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this contract.** Phase 4 renders four new surfaces on the one route `/` — the **gate**, the **order list**, **order detail** and **time on this order** — plus the **header** that persists on three of them, and it builds the five DESIGN.md primitives every later screen measures against. Requirements delivered: REQ-FR-48a, REQ-FR-58, REQ-NFR-2, REQ-NFR-4, REQ-NFR-4a, REQ-NFR-6 (ROADMAP.md §Phase 4). The server behaviour these screens render is already shipped and frozen (REQ-FR-4, REQ-FR-5, REQ-FR-7 … REQ-FR-11); REQ-NFR-5, REQ-NFR-7 and REQ-NFR-9 were validated in Phase 1 and remain binding on every surface added here.

**How to read it.** This contract **extends** `.planning/phases/01-scaffold-conventions/01-UI-SPEC.md` rather than restating it. The design system, the spacing scale, the type roles, the ink-permission set, the contrast floors and the ribbon contract were all locked there and are unchanged; this document states only what Phase 4 adds, exercises for the first time, or corrects. Where a figure was measured in DESIGN.md it is cited, never recomputed. Two composite ratios and one refusal are **computed in this document** and are marked as such.

**No question in this contract was put to the user this session.** Every value is locked upstream (cited), decided here from the design sources under CONTEXT.md's Claude's-Discretion clause (marked **[decided here]** with its reasoning), or an authored string marked **[written here]**. See `## Sources` for full traceability and `## Decisions Taken In This Document` for the seven discretionary calls.

**On the eight governed sentences.** They are defined exactly once, in `lib/copy/governed.ts`, as `{before, strong, after}` triples, and a build check fails on a duplicate literal anywhere under `app/`, `components/` or `lib/`. This document therefore refers to each of the eight **by key and by placement only** and never restates one, not even in prose. Phase 4's only governed-sentence renderings are `preview` — in the ribbon on all four surfaces (unchanged from Phase 1) and in the gate's disclosure. A prior phase's UI researcher silently moved the bold clause of `preview` while paraphrasing it; in this project that is a claims defect, not a copy nit, which is why nothing below quotes one.

### No eyebrow renders in Phase 4 — **[decided here]**

DESIGN.md calls the eyebrow the system's signature component, and it would be a natural fit for the three section labels this phase needs (*assets*, *governing docs*, the disclosure's heading). Phase 4 uses the `label` role instead, in `--cobalt-glow-ink`.

The reasoning, in order of weight. The eyebrow is **not one of the five primitives D-06 builds** (ribbon, record control, secondary control, focus ring, state marks), so nothing in this phase's scope calls for it. Rendering one would exercise **decorative-exemption register entry 2** — the 40×1 px `::after` rule at 0.35 opacity, 2.23:1 on the ground and 2.17:1 on the panel — for the first time, and would require a new `rgba()` token so the existing contrast check's alpha-compositing path can read it. `label` in `--cobalt-glow-ink` carries the same job at **8.62:1 on the ground and 7.59:1 on the panel**, with no exemption and no new token. Phase 4 therefore leaves the exemption register at exactly four entries with only entries 1 and 4 exercised.

> **Follow-up for whoever renders the first eyebrow (do not fix here).** `docs/design/decorative-exemptions.json`'s `eyebrow-trailing-rule` entry records its ink as `--cobalt`. DESIGN.md §The eyebrow and §The decorative-exemption register both say the rule is **`--cobalt-glow-ink` at 0.35 opacity**, compositing to `#39567B` on the ground and `#3F5D81` on the panel. The entry's ink name is wrong. It is not a Phase 4 blocker because no eyebrow renders, and correcting it is outside this phase's scope, but the first eyebrow will trip it.

### The 44 px label rule, read correctly

C-18 and DESIGN.md both state that *"every 44 px control carries a single tracked word and never a phrase."* Read literally that contradicts every 44 px control EXPERIENCE.md itself names — *Read the full preview limits*, *End this session and choose a different artisan*, *Report something else*, *No plate — say it in the note*, *Add a note*, *Sync now*. The figure behind the rule is vertical capacity: **1.30 lines of `label` at 200%, which is one line**, measured inside a box whose width is fixed.

**The rule, as Phase 4 applies it — [decided here]:** a 44 px control **whose width is fixed by a row of peers** carries one tracked word; a 44 px control **laid at content width** wraps and the control grows, because `min-height: 44px` is a floor and there is no maximum. This is the ribbon's own contract (`min-height: 44px`, `max-height: none`, C-15) and the governing-document row's (`min-height: 44px`, grows to 61 px, C-22), and it is the only reading under which EXPERIENCE.md's own named controls are conformant. Phase 4 lays every 44 px control at content width; none sits in a fixed-width row of peers.

### A correction to DESIGN.md's tinted-callout border, with its arithmetic — **[computed here]**

C-21 and DESIGN.md §Queue row and conflict card specify the conflict card's surrounding boundary as *"a 1 px border at 0.30 alpha of the tone."* Phase 4 is the first phase to render a conflict card, and that value does not clear the non-text floor.

0.30 alpha of `--dk-warn` `#fbbf24` composited over `--navy-deep` `#0c1e35` resolves to **`#544E30`**, relative luminance **0.075505**, which is **2.003:1** against the ground — below NFR-6's 3:1 by 1.0.

*Method, validated before the finding was trusted.* The same compositing and luminance routine reproduces two figures DESIGN.md states independently: 0.10 alpha of `--dk-warn` over `--panel-solid` resolves to **`#2D383C`** (DESIGN.md's own stated hex, to the byte), and `--viewer-ink` on that tint computes to **10.324:1** against DESIGN.md's stated 10.33:1, while `--dk-warn` on `--navy-deep` computes to **10.042:1** against DESIGN.md's stated 10.04:1. The routine agrees with the source on every figure the source states; the 2.003:1 stands.

**The resolution — [decided here]:** the conflict card's **surrounding boundary is 1 px `--control-border`** (4.07:1 against the page ground outside it, 3.58:1 against `--panel-solid` inside it). Everything else about the component is unchanged: the 3 px left rule stays **full-tone `--dk-warn`** at 10.04:1 on the ground; the head stays at the declared **0.10** tint, `--tint-warn-head` `#2D383C`; and `--viewer-ink` remains the **only** permitted ink in the head, at 10.33:1.

Three reasons, in order. C-5 closes the decorative-exemption register at exactly four entries and states that *"nothing else can be added to the list by argument"* — a fifth entry would need a DESIGN.md change, not a phase decision. DESIGN.md's own doctrine for a surface that does not read is *"raise the border and never the panel,"* and `--control-border` is *"the token for every meaning-bearing boundary."* And the card's perceivability never depended on that border anyway: it is read by its 3 px full-tone left rule, exactly as `--panel-solid` is read by its `--control-border` edge.

> **Carry this back into DESIGN.md before Phase 6 renders the real conflict cards.** Phase 6 renders twelve of them, and whoever builds them will otherwise reach for the 0.30 alpha the source still states. Recorded here, in the body rather than in a changelog, following DESIGN.md's own practice for a number other people hold.

## Decisions Taken In This Document

CONTEXT.md left three areas to research and planning and this document resolves the visual and interaction half of each; the orchestrator named seven calls in total. Each is stated with the sources that forced it.

### Decision 1 — The four screens' concrete layouts

Resolved in full under `## Phase 4 Surfaces` below, against C-9's horizontal arithmetic, C-10's vertical budget, C-12's three bands of reach and C-11's safe area. Two structural calls are worth naming here because later phases inherit them.

**The gate renders no header.** C-28 says the header persists "on every screen", but all four of its contents are undefined at the gate: there is no acting account (that is what the gate is *for*), back has no in-app target (C-29: *"the gate is not reachable backwards"*), and connectivity and the queue count are Phase 6. An empty header would cost 56 px of the gate's body for chrome with nothing in it, and a back control there would contradict C-29 outright. The gate's body is therefore `707 − 89 = **618 px**` at 100% and `707 − 309 = **398 px**` at 200%.

**The header's two Phase 6 slots are absent from the DOM; the 56 px height is kept.** The elements are absent, not empty: a connectivity badge in Phase 4 would have nothing to report, and one reading *online* from `navigator.onLine` alone is precisely the lie C-37 names (*"in a plant, an attached access point with no uplink is the common case, and a badge that trusts the browser lies"*); a queue count would count a queue that does not exist. EXPERIENCE.md's own rule for a surface that is not there is absence, not an empty state (FR-R6). The **height** stays at `--header-h` 56 px because C-10's 56 / 68 figures are the measured budget every other screen's body is derived from, and shrinking the header for one phase then restoring it in Phase 6 would re-derive the whole vertical budget twice for no gain — the opposite of C-10's discipline.

### Decision 2 — The time-on-order surface reads the record and nothing else

FR-58 says *"every segment, its source, any measured offset; nothing withheld."* Phase 4 renders **exactly the fields `OrderClock` carries**, with a stated mapping so "nothing withheld" is provable rather than asserted, and **no figure the phone derived**.

| `OrderClock` field | Renders as |
|---|---|
| `order_id` | The surface's `<h1>`, and the `id` in the URL |
| `account_id` | The header's account name (`GET /api/session` → `account.name`) |
| `elapsed_s` | The clock-level **ACCRUED** figure — the server's own sum (FR-10) |
| `segments[].source` | The segment row's **SOURCE** pair: a state mark plus the word `SERVER-STAMPED` or `DEVICE-CLAIMED` |
| `segments[].opened_at` | **STARTED** |
| `segments[].closed_at` | **ENDED**, or the word `RUNNING` where it is `null` |
| `segments[].device_claimed_opened_at` | **DEVICE CLAIMED** — present only where the field is present |
| `segments[].device_offset_s` | **MEASURED OFFSET** — present only where the field is present |

**Where `source` is `"server"` the two device pairs are absent, not empty.** The fields are absent from the record (the type marks both optional), so there is nothing withheld; rendering an empty row would state a field the record does not carry. This is FR-55's present-fields-versus-absences discipline read the right way round: the record's own optionality is the fact.

**No per-segment duration renders, deliberately.** It is not a field of `OrderClock` — it would be arithmetic the phone performed on two instants — and the one surface whose entire purpose is the provenance of instants does not mix server values with phone arithmetic. Both instants render in full, so the artisan can read the interval off them. `ACCRUED` renders because `elapsed_s` **is** a server field (FR-10: accrued hours are computed server-side). A later phase must not "add the obvious missing column".

**Instants and durations, two rules, applied everywhere:**

- **Every instant** renders as `<time datetime="{the server's own ISO string, unmodified}">{YYYY-MM-DD HH:MM:SS, local}</time>` at `figure` (mono 13 px, `tabular-nums`). The machine-readable value is the server's byte-exact string — comparable to the network panel in the way C-32 and C-54 ask of every reviewer surface — and the human-readable text is the reading an artisan wants. Both come from the same field, so they cannot drift. One format always, never conditional on whether the instants share a calendar day: a day boundary is never hidden.
- **Every duration** renders as `H:MM:SS` at `figure`. A base-60 regrouping of an integer second count is lossless and reversible, so it is a rendering and not a claim. `MEASURED OFFSET` therefore reads `0:03:12` for a 192-second offset.

**The source mark — the phase's hardest mark question.** REQ-NFR-6 and the ROADMAP forbid carrying this distinction by hue alone, and C-33's set of seven shapes is **closed**.

| `source` | Mark | Block tone | Word tone | Word |
|---|---|---|---|---|
| `"server"` | **filled square** | `--dk-good` 8.47:1 on the panel | `--dk-good` 8.47:1 | `SERVER-STAMPED` |
| `"device_reconciled"` | **hollow square with a centred dot** | `--dk-warn` 8.84:1 on the panel | `--viewer-ink` 12.64:1 | `DEVICE-CLAIMED` |

The filled square means *bound*, and DESIGN.md's status set assigns `--dk-good` to *"recorded · matched · reconciled · clock running"* — a server-stamped segment is recorded, so the shape and the tone are both the set's own.

The device-claimed case is the judgment call. The **filled diamond** is excluded: it means *"the server declined for a stated reason"*, and the server declined nothing. The **half-filled square** is excluded: it means *"in hand, not yet bound"*, and the segment **is** bound — FR-11 says the server retained both the device-claimed time and the measured offset. An **eighth mark is forbidden** by C-33. What differs is not the binding but the **provenance of the instant**, and the closed set's mark for that is the hollow square with a centred dot: *"kept, and unresolved"*, which C-38 glosses as *"the mark of a record whose middle is unknown, not of a mistake."* A device-claimed start is kept and its true instant is known only within the measured offset. Its tones come from C-38's own pairing of that mark (`--dk-warn` block, `--viewer-ink` word), and C-38's note that **`--dk-warn` here states *unresolved*, never *wrong*** transfers with it. C-33's "used by" column lists only the referral case; Phase 4 extends that mark's **usage** without changing its **meaning**, which is the distinction the closed set exists to protect.

**And the mark is never the only channel.** Every state carries three (C-33: fill, border, mark) plus the source **word**, which is text and carries no colour channel at all. A reader with no colour perception reads `SERVER-STAMPED` or `DEVICE-CLAIMED` and is told the whole thing.

### Decision 3 — The clock control and the live tick

**Geometry and variant.** One 130 px record control on order detail (C-40), using the record-control primitive's `clock` variant: box `130 × 130`, `--radius-control` 10 px, `control-label` clamped, fill `--record-fill`, ink `--record-ink` at 7.75:1, **no rest border**, **no armed state**.

*Why no rest border.* Decorative-exemption register entry 3 is scoped by its own text to *"the accept side of every record-binding pair"*, and the shape-cue job it does exists because FR-22 asserts parity between two controls. The clock control has no partner. Omitting the border adds no exemption and removes a below-floor value from the build; the control is identified by its fill against the ground at 7.75:1. Its **pressed** boundary therefore runs 0 → 4 px rather than 1 → 4 px, which is a larger perimeter change, not a smaller one.

*Why no armed state.* C-17 scopes the armed state to accept (*"armed (persistent, accept only)"*). NFR-8's deliberate confirm defeats an incidental brush that would bind something unwanted, and neither clock action can: opening an open order is idempotent and creates no second segment (FR-7), and closing a closed one returns a **stated** conflict with nothing lost (FR-8). **Single tap, no confirm step.**

**Three states, one in-place label swap.**

| Clock state (from `OrderClock.segments`) | Label | The act |
|---|---|---|
| No segments | `OPEN` | `POST /api/orders/{id}/open` — starts the first server-stamped segment |
| A segment with `closed_at === null` | `CLOSE` | `POST /api/orders/{id}/close` — ends the current segment |
| Segments exist, none running | `REOPEN` | `POST /api/orders/{id}/open` — **appends** a new segment; prior segments are retained (FR-9) |

Same box, same hit area, same position in the reading order, in all three states. The accessible name is the visible label and swaps with it (C-41). This is a **third use of C-40's two-use in-place-swap mechanic** and not a new one: `RECORD` → `STOP` is licensed because *"both are record-binding controls under NFR-1, and being the same object is how both meet the 20 mm floor"*, which is exactly the clock's situation. `REOPEN` is a distinct label from `OPEN` because reopening appends rather than resumes, and that difference is a fact about the record.

**The fill never moves across the three states.** The fill channel is exhausted by arithmetic (C-17: 1.199:1 between the two fills, and even white is 2.16:1 from `--record-fill`). The state is carried by the **label** — a word, not a hue — and by the elapsed figure beside it.

**No state mark on the clock control.** The closed set of seven contains no mark meaning *a clock is running*; DESIGN.md's status set assigns `--dk-good` to "clock running" as a **tone** with no shape. A word and a figure carry the state with no colour channel, and no eighth mark is invented.

**The live tick — what changes, how often, what is heard, and what Reduce Motion does.**

| Aspect | Contract |
|---|---|
| **What changes** | Exactly one text node: the elapsed figure, `figure` role (mono 13 px / 1.3 / 0.04em, `tabular-nums`) in `--viewer-ink`. Nothing else on the screen changes as the clock ticks — no colour shift, no pulse, no dot, no progress indicator, no layout reflow (the tabular figure's glyph box is fixed, which is C-7's stated reason for `tabular-nums`: *"a queue count and a device offset that do not jitter as they change"*). |
| **Format** | `H:MM:SS`, per Decision 2's duration rule. |
| **Cadence** | Once per second. ROADMAP SC-1 requires the artisan to see it tick, and a minutes-only figure does not visibly tick, which would leave the criterion unprovable at the surface. |
| **SC 2.2.2 (Pause, Stop, Hide, Level A)** | A per-second auto-updating figure is auto-updating information under **SC 2.2.2**, and the criterion is satisfied by its **"essential" exception**, claimed explicitly here. The exception holds because a paused or stopped clock display would show a figure that is **false** — the segment is still running on the server — and the whole purpose of the surface is that the artisan sees time accruing (ROADMAP SC-1). There is no pause, stop or hide control, and no frequency control, because every one of them produces a wrong number rather than a slower true one. **The argument is made rather than assumed**, following EXPERIENCE.md's own precedent: it considered "essential" for the armed accept's SC 2.2.1 timer, **rejected** it, and recorded why — so the exception has to be earned each time. Here it is earned; there it was not. **axe cannot detect this criterion, so invariant C7 will not catch it** — it is recorded in this contract and in §Accessibility Floor instead, which is the only place it can be held. |
| **Derivation** | The displayed figure is the last server-read `elapsed_s` plus locally measured wall-clock time since that read, re-anchored on every fresh server read. Interpolation versus polling is planning's call (CONTEXT.md); **the disclosure is not**. |
| **Disclosure** | The authored line **"The server stamped this segment's start; the seconds since are counted on this phone."** renders permanently beneath the figure at `label` in `--viewer-ink-dim`. It is true under either mechanism. |
| **What a screen reader hears** | **Nothing, per second.** The figure carries `role="timer"`, whose implicit `aria-live` value is **`off`** — the correct role for a numerical counter, announced on demand when the user reaches it, never pushed. **`aria-live` is never set on this element**, and the role is there partly so nobody "improves" it to `polite`. C-41 reserves polite live regions for queue-state changes and states plainly that *"an artisan mid-capture is not interrupted."* |
| **What *is* announced** | The **label swap**. C-41: *"where a label swaps, the accessible name is the visible label and it swaps with it."* The state change announces; the tick does not. |
| **Reduce Motion** | **The tick continues.** It is a value changing, not an animation: there is no transition, transform or opacity change on the figure in any state. See §Motion for Phase 4's complete Reduce Motion position. |

**NFR-4 and the phase-bounded gap in the write-acknowledgement contract.** The clock control's NFR-4 confirmation is the **90 ms perimeter press change** — boundary 0 → 4 px in `--record-ink` at 7.75:1 on the fill, plus radius 10 → 4 px — which completes inside the 100 ms budget and falls wholly outside the region a gloved thumb occludes while resting on the control. Both properties change, which is what carries NFR-4 on iOS where there is no second channel (NFR-4a).

The **label swap** arrives when the server answers, and that is later than 100 ms. C-40's write-acknowledgement contract says *"there is no code path in which the artisan waits on the server"* — but that property is the **queue path's**, and Phase 4 is online-only with no queue (Phase 6). So in Phase 4 the artisan does wait on the server for the label swap. **Recorded as a deliberate, phase-bounded gap, closed by Phase 6**, in the same shape as D-04. Between the tap and the answer, **nothing changes after the press transition completes**: no spinner (C-40 forbids one on a clock action outright), no disabled state, no interim label. The control stays tappable, because open is idempotent and close-on-closed returns a stated conflict.

**Haptics (REQ-NFR-4a).** A short vibration fires on the clock control only, feature-detected via `'vibrate' in navigator`, **never as the sole channel** and **never on a non-record-binding control**. On iOS the Vibration API does not exist and the visible change carries NFR-4 alone. The call site lives in the record-control primitive and nowhere else.

**A clock action's refusal.** `not_open` (closing a closed order — ROADMAP SC-3 requires this reachable) and `order_closed` render as a conflict card immediately **above** the clock control: filled diamond, `--dk-warn`, the code's name in the tinted head, and the server's own `detail` sentence at `prose-sm` in the untinted body. **No action row** — see the general rule under Decision 5. The card's slot carries **`role="status"`** (implicit `aria-live="polite"`): unlike the order list's refusal, this one appears *during* the screen's life in response to a tap, so a polite announcement is the only way a screen-reader user learns of it. Focus stays on the clock control, which was not removed from the DOM.

### Decision 4 — FR-48a's two gate states

**One component, one rendering, two states of the gate screen.**

| | First entry | Re-entry |
|---|---|---|
| `<h1 class="screen-title">` | **Choose an artisan** | **Choose an artisan** |
| The long-form disclosure | **Open**, as the leading content of `<main>` | **Closed.** In its place, one 44 px control: **Read the full disclosure** |
| `preview` | In full at `prose` 16 px, inside the disclosure | In full at `prose` 16 px, above the control — the short form C-30 names |
| The FR-48a disposition sentence | In full at `prose` 16 px, inside the disclosure, **below** `preview` | Reached by the control |
| The three persona doors | **Present and live**, below the disclosure | Present and live |

**The disclosure is in document flow, above the doors — it never overlays them.** `role="dialog"`, named by `aria-labelledby` pointing at its `<h2 class="label">` *Enforced and authored*, `--panel-solid` fill, 1 px `--control-border`, `--radius-card` 16 px, `{spacing.4}` 16 px padding, **no shadow, no blur**. Reopening it on re-entry replaces the control in place, and focus moves to the `<h2>` — C-41's rule for an in-place replacement inside a screen. The reopened disclosure carries **no close control**: nothing in this product asks to be put away, the doors stay live below it, and a close affordance on a disclosure is one step from the dismiss the ribbon is forbidden.

**Two parts of the sources' stated shape are deliberately not implemented, and this is the phase's one open tension with EXPERIENCE.md.**

- **`aria-modal="true"` is never set.** It hides everything outside the dialog from assistive technology, which would make the **ribbon unreachable by rotor** on the gate — a direct breach of C-15 (*"reachable by rotor on every screen, never `aria-hidden`"*) and of C-30's *"on every screen without exception"*. The ribbon's permanence outranks the dialog's modality. `role="dialog"` alone gives the role the sources name and costs nothing.
- **The scroll lock is not implemented as a document `overflow: hidden`.** At 200 % text the ribbon alone is 309 px and the disclosure is about 1025 px against a 398 px gate body; a document scroll lock would clip a governed sentence, breaching C-30 and SC 1.4.4, which NFR-9 fails the build on. There is also nothing behind the dialog to lock: it does not overlay, so the property a scroll lock protects does not exist here.

There is consequently **no acknowledge control and no forced dismissal on first entry**. FR-48a requires the gate to *state* the split before any claim is met, and it does — in full, above the doors, on the screen the artisan arrives at. It does not require an acknowledgement, and forcing one would be the only place in the product where a disclosure must be tapped away, which is the shape of a dismiss. **Modal depth is one and there is exactly one dialog in the build** (C-29), satisfied.

> **Flag for EXPERIENCE.md.** EXPERIENCE.md §Navigation contract and §Component Patterns both say *"`role="dialog"` with a scroll lock"*, and UJ-1 step 2 says *"the gate opens over it"*. The resolution above is the only reading under which the ribbon stays a permanent, rotor-reachable landmark and no governed sentence is clipped at 200 %. It should be recorded in EXPERIENCE.md rather than rediscovered by Phase 5.

**The FR-48a disposition sentence needs a home, and there is a precedent for it.** It is quoted from EXPERIENCE.md, it is not one of the eight, and the set of eight is closed — adding a ninth requires `check-governed.mjs`'s closed-set assertion to change in the same commit. `lib/copy/governed.ts` already carries exactly this case: `PLATFORM_413` is exported *"under its own name (not one of the eight; D-07)"*. **The disposition sentence takes the same shape** — its own named export beside `PLATFORM_413`, defined once, outside `check-governed`'s closed set of eight but inside the duplicate-literal sweep and the claims audit's roots. The check must additionally assert it is **not** a member of `GOVERNED`.

**The three persona doors** are 44 px secondary controls (C-18), not 130 px. Choosing a persona mints a session; it binds no record, and C-41's record-binding set is enumerated (*shutter, record, stop, accept, reject, submit*). Each door is laid at content width, `--surface-inset` fill, 1 px `--control-border` (4.49:1 on that fill), `--radius-control` 10 px, and contains, in DOM order:

1. The artisan's **name** at `object-title` in `--viewer-ink` (15.84:1 on the inset fill).
2. The **competency** at `label`, uppercase, in `--viewer-ink` — *"MILLWRIGHT, RED SEAL"*, as the door says (C-31).

**No ARIA name override.** The accessible name is computed from the door's own visible text in DOM order, so visible label and accessible name are identical by construction, with no `aria-label` to drift. The name comes first because the account is the thing being chosen. Visual order matches DOM order; no CSS reordering anywhere on this screen.

### Decision 5 — `order_not_found`'s placement, shape and announcement (D-02)

**Placement.** Inside `<main>` on the **order list**, immediately after the `<h1>` and before the first order row. Focus moves to the `<h1>` on arrival with no exception (C-41), so the refusal is the very next thing in reading order, followed by the artisan's own orders.

**Shape.** The conflict card's tinted-callout anatomy (C-21), with one omission and one correction:

| Zone | Specification |
|---|---|
| Tinted head | `--tint-warn-head` `#2D383C` (0.10 alpha `--dk-warn` over `--panel-solid`), 3 px left rule in **full-tone** `--dk-warn` (10.04:1 on the ground), **1 px `--control-border`** surrounding border (see §Color for why, not 0.30 alpha of the tone), `--radius-card` 16 px with `overflow: hidden` so the tint respects the radius. Carries the **filled diamond** state mark (`--dk-warn` block at **7.22:1** on the tint, computed here) and the conflict's name at `label` in **`--viewer-ink` only** (10.33:1 — the one permitted ink on a tinted head). |
| Untinted body | Plain `--panel-solid`, directly below the head, carrying `CONFLICT_COPY.order_not_found.sentence` at `prose-sm` in `--viewer-ink` (12.64:1). **Secondary prose lives in the body and never in the head** — the structural consequence of the tint. |
| Action row | **Omitted.** |

**The action row is omitted, and that is not the dismissive-OK failure C-36 forbids — it is the opposite.** `order_not_found`'s only action in `conflicts.ts` is *Discard*, which is a queue operation: nothing was queued, so there is nothing to discard and offering it would be false. The next act is the screen the card is standing on — the artisan's own orders, immediately below it. The general rule, which Phase 6 can consume unchanged:

> **On an online surface, a conflict card's action row is omitted when every action in the code's list is either a queue operation or a control already present on the screen. The actions themselves are never re-worded, never replaced by a dismissive *OK*, and never invented.**

The same rule governs the clock's `not_open` card (Decision 3), where the code's one meaningful action, *Open the order*, is the 130 px control directly beneath it.

**The mark is from the closed set, used for its stated meaning.** The filled diamond means *"the server declined for a stated reason"* — which is exactly what `GET /api/orders/{id}` did. No new mark.

**No sixteenth surface, and the URL must not lie.** The client issues `history.replaceState` to `?s=orders` and renders the refusal from the in-memory result of the failed attempt, **not** from the URL. Reason: `s` names the current screen (D-01), and leaving `s=order` in the URL while showing the order list would make screen identity — which is addressable state (C-27) — false. **Recorded consequence: the refusal does not survive a reload.** That is deliberate. A reviewer tests the byte-identical-refusal boundary at the API, which is where SM-1's actual test lives and where the refusal is genuinely uniform; a client screen is not the evidence.

**Announcement: no live region — [decided here].** The card is static content present at the screen's first render, reached by the focus-to-heading move plus one forward step. A live region populated at mount announces unreliably and would compete with the heading announcement the focus rule guarantees; C-41 reserves polite live regions for state changes during a screen's life, which is why the clock's refusal card gets one and this one does not. The card carries **no role and no landmark**: it has no actions to group, and a fifth region on a surface that already has a labelled `section`, a `banner` and a `main` is rotor noise for no gain.

**D-02's claim, protected.** The wording is `conflicts.ts`'s own and is never composed at the call site, so an unowned order and a nonexistent one are indistinguishable in the copy exactly as they are on the wire. **Nothing rendered on this surface comes from the URL**: the `id` is a lookup key passed to a fetch path and is never rendered as text, so a deep link to a bad id can only ever show this one sentence and never an attacker-chosen string.

### Decision 6 — The pinned referral entry bar: **omitted in Phase 4**

This is the one place this phase's scope and the design source are in direct tension, and it is flagged as a decision rather than a reading.

EXPERIENCE.md §Interaction Primitives states that *"exactly one element in the build is pinned to the viewport: the referral entry bar on order detail"*, and C-16 specifies it in full. Referrals are **Phase 9** — 04-CONTEXT.md's Phase Boundary excludes *"the referral entry and its screens (P9)"* verbatim.

**Order detail in Phase 4 renders no bar at all — not a disabled one, not a placeholder.**

Four reasons. A disabled 44 px target is a control that announces itself and refuses, which is the false affordance this product avoids everywhere; EXPERIENCE.md's own rule for a capability that does not exist is that *"the surface is absent, not empty-stated as though a request had failed"* (FR-R6). C-16 is a **constraint on the bar when it exists** — *"it may carry a control only; a governed sentence may never be sticky or fixed"* — not a requirement that order detail always carry one. A disabled bar would cost 60 px of every order-detail viewport for a control that does nothing, which is the opposite of C-16's *"charged honestly rather than borrowed"*. And 01-UI-SPEC's standing discipline is explicit: *"do not build placeholders for them."*

## Motion

## Accessibility Floor

Locked by C-41, EXPERIENCE.md §Accessibility Floor, REQ-NFR-2, REQ-NFR-5, REQ-NFR-6, REQ-NFR-7, REQ-NFR-9. Phase 4's additions to what the build gates on:

- **WCAG 2.2 Level AA in full**, plus SC 1.4.6 (7:1 text) and SC 2.5.5 (44 × 44). CI fails on any A or AA violation, on any breach of NFR-1 or NFR-2, and on any below-floor contrast pair not matched in the four-entry register.
- **Targets.** Every non-record-binding target is at least 44 × 44 CSS px (REQ-NFR-2). The one record-binding control is 130 px, the design figure — 20 mm physical on the densest approved handset, never derived from a nominal 96 px/inch.
- **Focus on a screen change.** Focus moves programmatically to the new screen's `<h1>` on every transition without exception, including the gate's replace and every in-place replacement inside a screen. The `<h1>` carries `tabindex="-1"` so it is programmatically focusable but not in the tab order. Focus is **never** left on an element that has just been removed from the DOM.
- **SC 2.2.2 Pause, Stop, Hide (Level A) — claimed under the "essential" exception, and recorded because no tool can catch it.** The only auto-updating content in Phase 4 is the clock's per-second elapsed figure on order detail. It has no pause, stop, hide or frequency control, because every one of them would leave a **false** figure on screen while the segment continues to run on the server, and the artisan seeing time accrue is the point of the surface (ROADMAP SC-1). The argument is made rather than assumed: EXPERIENCE.md considered "essential" for the armed accept's SC 2.2.1 timer, rejected it, and recorded why — so it is earned here and was not there. **axe does not detect SC 2.2.2, so invariant C7 will not catch it**; this contract is where it is held. Full reasoning in Decision 3.
- **Screen reader.** Every interactive element carries role plus state. Where a label swaps — `OPEN` → `CLOSE` → `REOPEN` — the accessible name is the visible label and swaps with it. The ribbon remains a labelled landmark, reachable by rotor on all four surfaces, never `aria-hidden`, and **never announced as a region on a screen change**; `aria-modal` appears nowhere in the build, which is what preserves this on the gate. The elapsed figure carries `role="timer"` and its implicit `aria-live: off` is never overridden. The clock's refusal card carries `role="status"`; the order list's refusal card carries **no** live region, because it is present at first render and is reached by the focus-to-heading move.
- **Reading order.** DOM order equals visual order on all four surfaces; no CSS reordering anywhere. Focus traversal follows reading order.
- **200 % text (SC 1.4.4).** Every surface operable; nothing hides, nothing shortens, nothing is truncated. The gate scrolls by roughly 680 px, order detail by roughly 450 px + reflow, the time surface by its own row growth. Vertical scroll is an operable screen; a truncated disclosure is not.
- **320 CSS px (SC 1.4.10).** Operable with no two-dimensional scrolling, including at the 130 px record-binding size. Every `<dt>`/`<dd>` pair wraps rather than forcing a horizontal scroll.
- **State is never conveyed by hue alone.** Every state in Phase 4 carries a shape from the closed set of seven **and** a word from a closed vocabulary. A reader with no colour perception is told everything: `SERVER-STAMPED` versus `DEVICE-CLAIMED`, `OPEN` versus `CLOSE` versus `REOPEN`, the order's status word, the conflict's name.
- **Reduce Motion.** The 90 ms press transition is retained; Phase 4 has nothing else that moves (§Motion).
- **No gesture-only action**, no swipe, no drag, no long-press, no pull-to-refresh, no infinite scroll, no carousel, no toast carrying the only copy of a fact, and no confirmation dialog asking *are you sure* about something the app was never going to discard.
- **Every consequential control is idempotent.** A repeated tap on `OPEN` makes no second segment (FR-7); a repeated tap on `CLOSE` against a closed order returns a stated conflict and loses nothing (FR-8).
